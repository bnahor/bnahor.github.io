The engineering choice.

Contact-rich environments do different amounts of solver work. That makes lockstep GPU physics an awkward fit for some workloads. Pippin decouples physics, rendering and policy inference, and overlaps them across groups of environments.

CPU   physics   [ A ][ B ]
GPU   render    [ A ][ B ]
GPU   inference    [ A ][ B ]

The stack includes a Rust physics engine, pluggable physics backends, a batched Metal renderer, Python bindings and seeded procedural scene generation.

What this proves.

These are recordings of the real Python example, not an animation approximating the simulator. The browser plays the captured frames; it does not execute Rust or Metal.

CONTROLLER AND LIMITATIONS

The arm follows inverse-kinematics waypoints using position actuators. There is no trained grasp policy. This is one 16-environment seed, not a general manipulation-success benchmark. The project is early and its APIs are changing.
